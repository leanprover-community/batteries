                              @[inline]
                              unsafe def withPtrEqUnsafe {α : Type u} (a b : α) (k : Unit → Bool) (_h : a = b → k () = true) :
                              Bool

                              Returns true if a and b are represented by the same pointer at runtime, or k () otherwise.

                              If k is a function that performs an equality check on a and b, then this operation can be used to short-circuit the equality check for pointer-equal input.

                              This function is unsafe because its result is not equal to k () if α includes computationally irrelevant data like types. Consider the example α := Prop, a := True, b := False, k := fun _ => false. In this case, a = b → k () = true is true, but a and b have the same runtime representation of an erased type, so ptrEq a b is true and this function returns true, even though k () is false.

                              withPtrEq is a safe version of this function, for which the compiler checks that α does not include such data.

                              Equations
                              • withPtrEqUnsafe a b k _h = if ptrEq a b = true then true else k ()

                                noncomputable def withPtrEq {α : Type u} (a b : α) (k : Unit → Bool) (_h : a = b → k () = true) :
                                Bool

                                Returns k (), but skips evaluating k () and returns true if a and b are represented by the same pointer at runtime.

                                If k is a function that performs an equality check on a and b, then this operation can be used to short-circuit the equality check for pointer-equal input.

                                This is only correct if pointer-equal values of α are equal. This is not the case if values of α can contain types or type formers, because these are erased at runtime. For example, True and False have the same runtime representation, but withPtrEq True False (fun _ => false) _ must return false. Therefore, the compiler refuses to compile a definition that uses withPtrEq unless it can check that values of α cannot contain types or type formers. In particular, withPtrEq cannot be used polymorphically: it can be used at types such as List Nat or Fin n, but not at List β if β is a type variable.

                                Use withPtrEqUnsafe to bypass this check.

                                Equations
                                • withPtrEq a b k _h = k ()

                                        β

                                        Checks whether a is exclusive at runtime, applying k to the verdict. This can be used, for example, to skip caching values that are not referenced from anywhere else. This function is safe because of the proof obligation h, which ensures that the result does not depend on the answer.

                                        This function is a safe wrapper around isExclusive. Logically, it is k false.

                                        Being exclusive does not imply that a can be updated in place: that also requires the caller to own a rather than borrow it.
