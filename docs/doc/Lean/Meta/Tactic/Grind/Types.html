      def Lean.Meta.Grind.eqCongrSymmPlaceholderProof :
      Expr

      We use this auxiliary constant to mark delayed symmetric congruence proofs. Example: a = b is symmetrically congruent to c = d if a = d and b = c.

      Note: We previously used congrPlaceholderProof for this case, but it caused non-termination during proof term construction when a = b = c = d. The issue was that we did not have enough information to determine how a = b and c = d became congruent. The new marker resolves this issue.

      If congrPlaceholderProof is used, then a = b became congruent to c = d because a = c and b = d. If eqCongrSymmPlaceholderProof is used, then it was because a = d and b = c.

      Example: suppose we have the following equivalence class:

      {p, q, p = q, q = p, True}

      Recall that True is always the root of its equivalence class. Assume we also have the following two paths in the class:

      1. p -> p = q -> q = p -> True
2. q -> True

      Now suppose we try to build a proof for p = True. We must construct a proof for (p = q) = (q = p). These equalities are congruent, but if we try to prove p = q and q = p using the facts p = True and q = True, we end up trying to prove p = True again. In other words, we are missing the information that p = q became congruent to q = p because of the symmetric case. By using eqCongrSymmPlaceholderProof, we retain this information.

          def Lean.Meta.Grind.getLitKind (e : Expr) :
          MetaM LitKind

          Classifies the application e. For example, BitVec and Fin are parametric literals, but Nat is not. The types of nonparametric literals are reduced using whnfD, but BitVec and Fin must occur syntactically.             def Lean.Meta.Grind.isInterpreted (e : Expr) :
            MetaM Bool

            Returns true if e is True, False, or a literal value. See Lean.Meta.LitValues for supported literals. grind assumes distinct interpreted terms denote distinct values, so a literal is interpreted only if it is in normal form, and in particular its type must be structurally a supported builtin type, with a numeral parameter for Fin/BitVec. LitValues recognizes literals up to whnfD on their types, e.g. (1 : BitVec w) for def w := 32, but the canonicalizer does not unfold w, and (1 : BitVec w) and (1 : BitVec 32) would be distinct interpreted terms denoting the same value.

            The type of a literal is read from e itself. For negated literals, both the outer and inner types must be the same normal type. Rat, Float, and Float32 literals are never interpreted. A literal of a signed fixed-width type is interpreted only in the form produced by its ToExpr instance, i.e., when it is in range: the canonicalizer reduces OfNat numerals modulo 2^w, but (200 : Int8) and (-56 : Int8) still denote the same value, as do -0 and 0. Assumes e has no assigned metavariables.

                                                                                                                              inductive Lean.Meta.Grind.SolverTerms :
                                                                                                                              Type

                                                                                                                              Each E-node may have "solver terms" attached to them. Each term is an element of the equivalence class that the solver cares about. Each solver is responsible for marking the terms they care about. The grind core propagates equalities and disequalities to the theory solvers using these "marked" terms. The root of the equivalence class contains a list of representatives sorted by solver id.                                                                                                                                                                                                                                         partial def Lean.Meta.Grind.instantiateMVarsResolvingDelayed (e : Expr) :
                                                                                                                                                                                                                                        MetaM Expr

                                                                                                                                                                                                                                        Similar to instantiateMVars, but also resolves the delayed assignments ?m #[xs] := ?pending created inside the current withNewMCtxDepth block, which is entered by grind during its startup. instantiateMVars only resolves a delayed assignment when ?pending's assignment val is ground (no unassigned expression metavariables). This ground restriction exists because val may contain metavariables that have xs in their scope. For example, if xs = #[x] and val = ?n + x where x is in the scope of ?n, then mkLambda creates fun x => ?n + x. If ?n is later assigned to f x, the term becomes ill-formed with a dangling free variable.

                                                                                                                                                                                                                                        This scenario cannot occur here: in a grind proof, val only contains metavariables created before withNewMCtxDepth, and they cannot contain free variables created by grind, so the conversion is safe. Delayed assignments created before withNewMCtxDepth are left untouched, as they are meant to be resolved by other tactics.

                                                                                                                                                                                                                                        partial def Lean.Meta.Grind.getProofInfo (e : Expr) :
                                                                                                                                                                                                                                        GrindM ProofInfo

                                                                                                                                                                                                                                        Returns a ProofInfo summary of e by following metavariable assignments without constructing the instantiated expression. Collects free variables and synthetic sorry occurrences, and reports whether the traversal encounters an unassigned metavariable at the current depth.

                                                                                                                                                                                                                                        For an ordinary metavariable application ?m as, combines the summary of ?m's assignment, if any, with the summaries of all arguments as, including arguments the assignment ignores. For a delayed assignment ?d #[xs] := ?p, summarizes ?p's assignment, removes xs from its free variables, and combines the result with the summaries of all arguments to ?d. The local declarations of xs are not traversed, so dependencies in binder types that would remain after resolving a partially applied delayed assignment are not included.

                                                                                                                                                                                                                                        Unassigned metavariables contribute no free variables or synthetic sorry occurrences. Only those at the current depth set hasUnassigned. During grind's protected withNewMCtxDepth block, outer-depth metavariables cannot be assigned, and their local contexts cannot contain free variables introduced by grind. Their eventual assignments may change the summary after the protected computation ends.

                                                                                                                                                                                                                                        Summaries of assigned metavariables with hasUnassigned = false are cached in State.proofInfos. A cached summary is reused only while the metavariable's assignment is the same expression. This avoids repeatedly traversing shared assignments, such as proofs used by nested case splits.

                                                                                                                                                                                                                                        Wraps e : type in let bindings for selected hoisted declarations. The proof may refer to hoisted free variables, directly or through metavariable assignments, even when those variables are absent from the current local context.

                                                                                                                                                                                                                                        Declarations are ordered as decls.front.reverse ++ decls.decls. Using getProofInfo, selects declarations referenced by e and recursively by the values of selected declarations. Each value may depend only on earlier declarations in this order. If the summary of e has hasUnassigned, keeps all declarations; if the summary of a selected value has hasUnassigned, keeps all earlier declarations, since later assignments may introduce dependencies on them.

                                                                                                                                                                                                                                        Dependency selection does not inspect type or declaration types. Declaration types are copied unchanged into the let bindings, so they must not refer to the hoisted free variables being bound. This postpones abstraction of the selected free variables in e until the delayed assignment is resolved, without instantiating e here. Returns e unchanged if no declarations are selected.
