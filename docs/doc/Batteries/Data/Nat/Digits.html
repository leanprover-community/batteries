    Digits #

    Conversions between natural numbers and big-endian or little-endian lists of digits in a given base. The digits are represented as elements of Fin base.

    The definitions are simple specifications. They are replaced at runtime, using csimp, by divide-and-conquer implementations, which are subquadratic when combined with the subquadratic multiplication and division of Nat.

    source
    def Nat.ofFinDigits {base : Nat} (l : List (Fin base)) :
    Nat

    Construct a natural number from a big-endian list of digits in the given base:

    ofFinDigits (base := 10) [2,3,4] = 234 -- 2*10^2 + 3*10^1 + 4*10^0
ofFinDigits (base := 2) [0,1,0,0] = 4 -- 0*2^3 + 1*2^2 + 0*2^1 + 0*2^0
ofFinDigits (base := b) [] = 0 -- any base, including "base 0" and "base 1"

    There are no valid inputs other than [] in "base 0". In "base 1", the only valid digit is 0 and therefore ofFinDigits (base := 1) l = 0.

    Equations
    • Nat.ofFinDigits l = List.foldl (fun (n : Nat) (d : Fin base) => n * base + ↑d) 0 l

            def Nat.toFinDigits (n base : Nat) :
            List (Fin base)

            Big-endian list of digits of a natural number n in a given base.

            When n is zero, the result is the empty list. Otherwise, the most significant digit is nonzero. The base should be at least 2, the result is always the empty list in "base 0" and "base 1".

            toFinDigits 123 10 = ([1,2,3] : List (Fin 10))
toFinDigits 4 2 = ([1,0,0] : List (Fin 2))
toFinDigits 0 12345 = ([] : List (Fin 12345))
            Equations
            • n.toFinDigits base = if h : n = 0 ∨ base < 2 then [] else have this := ⋯; (n / base).toFinDigits base ++ [Fin.ofNat base n]

                Subquadratic implementations #

                The definitions and theorems in the Nat.Internal namespace implement the functions above at runtime via csimp. They are public only because csimp requires it. They are not intended as part of the public API and they may change without warning.

                Each implementation splits its input roughly in half and falls back to a simple loop on small inputs, where computing base ^ k and splitting would cost more than it saves. The cutoffs are 16 digits for ofFinDigits and toFinDigitsFixed, and a split size of at least 8 digits for toFinDigits. They were picked by judgment rather than tuned by benchmarks. Correctness does not depend on them.
